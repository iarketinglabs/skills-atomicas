# Mapa de fontes e limites de atualização

Use referências primárias para confirmar sintaxe, comportamento e disponibilidade. A semântica do Git é mais estável que os planos, permissões e funcionalidades do GitHub; confirme versão, edição, configuração do repositório e documentação atual antes de recomendar um controlo específico.

## Engenharia de entrega e convenções

- [Google Engineering Practices: code review](https://google.github.io/eng-practices/review/)
- [Google Engineering Practices: small changes](https://google.github.io/eng-practices/review/developer/small-cls.html)
- [DORA: trunk-based development](https://dora.dev/capabilities/trunk-based-development/)
- [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/)
- [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html)

Estas fontes descrevem mecanismos e convenções; não definem a política de uma equipa. Benchmarks, taxas de merge e resultados de um fornecedor ou dataset são contextuais. Não os transforme em promessa universal de produtividade, qualidade ou segurança.
